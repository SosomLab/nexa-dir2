# 클라우드

Nexa Dir는 클라우드 저장소를 **두 가지 방식**으로 다룹니다. 목적이 다르니 먼저 구분하세요.

| | **링크 (Link)** | **직접 연결 (Connect)** |
| --- | --- | --- |
| 무엇 | PC에 이미 설치된 **동기화 폴더**를 내 PC 화면에 얹기 | 앱이 **클라우드 API에 직접 로그인** |
| 준비물 | OneDrive·Google Drive·Dropbox 클라이언트 설치 | 브라우저 로그인(1회) |
| 접근 방식 | 로컬 폴더 그대로(오프라인 가능) | 네트워크 요청(항상 온라인) |
| 계정 수 | 클라이언트가 붙인 계정만 | **제한 없음**(같은 서비스에 여러 계정) |
| 디스크 | 동기화된 만큼 차지 | **0** |

> 회사·학교 계정처럼 직접 연결이 막히는 경우(→ [한도와 제약](#한도와-제약))에도 **링크는 항상 동작**합니다.

---

## 링크 — 이미 있는 동기화 폴더 얹기

앱이 시작할 때 설치된 동기화 클라이언트를 **자동으로 찾습니다**(OneDrive 개인·비즈니스, Google Drive, Dropbox). 네트워크 요청은 전혀 하지 않습니다.

**추가하기** — 둘 중 편한 쪽으로:
- 메뉴 **Cloud → 링크 추가하기…** → 감지된 후보 선택
- **This PC 화면의 빈 곳 우클릭** → `{서비스} 링크`

추가하면 This PC 목록에 항목이 생기고, 드라이브처럼 들어갈 수 있습니다.

**항목별 메뉴**(Cloud 메뉴에서 해당 링크에 마우스를 올리면):

| 항목 | 동작 |
| --- | --- |
| 바로 가기 | 현재 탭에서 그 폴더로 이동 |
| 온라인 보기 | 브라우저에서 해당 서비스 열기 |
| URL 복사 | 주소를 클립보드로 — **프라이빗 창에 붙여넣어 다른 계정으로 접속**할 때 |
| 링크 해제 | 목록에서 제거(파일은 그대로) |

동기화 폴더가 사라지면(클라이언트 제거 등) 목록에서 자동으로 숨겨집니다.

---

## 직접 연결 — 브라우저로 로그인

동기화 클라이언트 없이, **디스크를 쓰지 않고** 클라우드를 탐색합니다. 같은 서비스에 계정을 여러 개 붙일 수 있습니다.

### 연결하기

1. 메뉴 **Cloud → 클라우드 직접 연결 → OneDrive / Google Drive / Dropbox**
2. 안내 창에서 **[브라우저 열기]**
3. 브라우저에서 로그인하고 권한에 동의
4. 창이 "연결되었습니다"로 바뀌면 완료 — This PC에 계정이 추가됩니다

> **다른 계정으로 연결하려면**: 브라우저에 이미 로그인된 계정이 있으면 그 계정으로 진행됩니다. 안내 창의 **URL을 복사해 프라이빗(시크릿) 창에 붙여넣으면** 원하는 계정으로 로그인할 수 있습니다.

### 할 수 있는 일

- 폴더 탐색 · 더블클릭으로 열기(임시 폴더로 받아 연결 프로그램 실행)
- **다운로드** — 로컬로 복사/붙여넣기·드래그 앤 드롭
- **업로드** — 파일·폴더 통째로(하위 폴더 재귀)
- 삭제 · 이름 변경 · 새 폴더
- 같은 계정 안에서 복사·이동(서버에서 처리 — 내려받지 않습니다)
- **계정 간 복사** — 예: Google Drive → OneDrive(임시 폴더 경유)

전송 중에는 로컬 복사와 같은 **진행 창**이 뜹니다(파일별 세그먼트·실제 바이트·취소). 폴더를 열 때 시간이 걸리면 `불러오는 중…` 행과 배지가 표시됩니다.

> **되돌리기(Ctrl+Z)는 클라우드에 적용되지 않습니다.** 잘못 지웠다면 각 서비스의 휴지통에서 복구하세요.

### 연결 해제

**Cloud → {계정} → 연결 해제**. 저장된 로그인 정보도 함께 삭제됩니다.

---

## 로그인 정보는 어디에 저장되나

- 갱신 토큰은 **Windows DPAPI로 암호화**되어 `data\secrets\`에 저장됩니다.
- DPAPI는 **사용자 계정 + 이 PC**에 묶입니다. 따라서 **포터블 폴더를 다른 PC로 옮기면 복호화되지 않아 재로그인**이 필요합니다 — 의도된 안전장치입니다(USB를 잃어버려도 토큰이 새지 않습니다).
- 비밀번호는 앱이 **보지도, 저장하지도 않습니다**. 로그인은 브라우저에서만 이뤄집니다.

---

## 내 계정 정보로 사용하기 (고급)

Nexa Dir는 세 서비스 모두에 **기본 Client ID를 동봉**하고 있어, 보통은 아무 설정 없이 바로 연결됩니다. 아래에 해당하면 **자기 것을 발급**해 쓰세요.

**직접 발급이 필요·유리한 경우**
- **Google Drive에서 100명 한도에 걸렸을 때** — 기본 ID는 전 사용자가 100명 한도를 나눠 씁니다. 자기 ID를 쓰면 그 한도와 무관해집니다.
- **7일마다 재로그인이 번거로울 때** — 자기 프로젝트를 프로덕션으로 게시하면 만료가 사라집니다.
- **회사 계정으로 OneDrive를 직접 연결해야 할 때** — 회사 테넌트에 앱을 등록하면 동의 정책을 우회할 수 있습니다.
- API 호출 한도(쿼터)를 전용으로 쓰고 싶을 때.

### 설정 파일에 넣는 방법

exe 옆 **`data\settings.cfg`**를 메모장으로 열고 아래 줄을 추가한 뒤 **앱을 다시 시작**합니다.

```ini
cloud_client_id_onedrive=00000000-1111-2222-3333-444444444444
cloud_client_id_googledrive=1234567890-abcdefg.apps.googleusercontent.com
cloud_client_secret_googledrive=GOCSPX-xxxxxxxxxxxxxxxx
cloud_client_id_dropbox=abcdefghij12345
cloud_client_secret_dropbox=klmnopqrst67890
```

| 키 | 값 | 필요 여부 |
| --- | --- | --- |
| `cloud_client_id_onedrive` | Entra 앱의 **애플리케이션(클라이언트) ID** | 선택 |
| `cloud_client_id_googledrive` | GCP OAuth 클라이언트 ID | 선택 |
| `cloud_client_secret_googledrive` | GCP 클라이언트 보안 비밀번호 | **ID를 넣었다면 필수** |
| `cloud_client_id_dropbox` | Dropbox 앱 **App key** | 선택 |
| `cloud_client_secret_dropbox` | Dropbox **App secret** | **ID를 넣었다면 필수** |

**규칙**
- 넣은 값이 **동봉 기본값보다 우선**합니다. 줄을 지우면 기본값으로 돌아갑니다.
- 값에 따옴표를 붙이지 마세요. 앞뒤 공백은 무시됩니다.
- **바꾼 뒤에는 기존 연결을 해제하고 다시 연결**하세요. 이전 ID로 받은 토큰은 새 ID에서 쓸 수 없습니다.
- OneDrive는 **시크릿이 없습니다**(있으면 안 됩니다). Google·Dropbox는 시크릿이 있어야 로그인이 완료됩니다.

---

### OneDrive — Microsoft Entra 등록 절차

1. <https://portal.azure.com> → **Microsoft Entra ID** → **앱 등록** → **새 등록**
2. **이름**: 아무거나(예: `Nexa Dir`)
3. **지원되는 계정 유형**: **모든 Microsoft 계정 사용자**
   (개인 계정만 쓸 거라면 개인 전용도 가능하지만, 회사 계정도 쓰려면 이 항목이어야 합니다)
4. **리디렉션 URI**: 플랫폼을 **퍼블릭 클라이언트/네이티브**로 고르고 값은 `http://localhost`
   > 반드시 **퍼블릭 클라이언트**여야 합니다. 웹(Web)으로 등록하면 시크릿을 요구해 실패합니다.
   > `http://127.0.0.1`은 포털이 등록을 거부하므로 `localhost`를 쓰세요.
5. 등록 후 **개요** 화면의 **애플리케이션(클라이언트) ID**를 복사
6. **API 권한** → Microsoft Graph → 위임된 권한 → `Files.ReadWrite`, `User.Read`, `offline_access` 추가
7. `settings.cfg`에 `cloud_client_id_onedrive=<복사한 ID>` 추가

**시크릿은 만들지 마세요** — Nexa Dir는 PKCE로 인증하며 시크릿을 보내지 않습니다.

---

### Google Drive — Google Cloud 등록 절차

1. <https://console.cloud.google.com> → 프로젝트 만들기
2. **API 및 서비스 → 라이브러리** → **Google Drive API** 사용 설정
3. **Google 인증 플랫폼(OAuth 동의 화면)** 구성 — 앱 이름·지원 이메일 입력
4. **데이터 액세스(범위)**에서 **`https://www.googleapis.com/auth/drive`** 추가
   > `drive.file`은 **앱이 만든 파일만** 보이므로 탐색기로 쓸 수 없습니다. 반드시 `drive`여야 합니다.
5. **대상**에서 사용할 계정을 **테스트 사용자**로 추가(게시 상태가 "테스트 중"인 동안 필수)
6. **클라이언트 → 클라이언트 만들기** → 유형 **데스크톱 앱**
7. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사
8. `settings.cfg`에 두 줄 모두 추가

```ini
cloud_client_id_googledrive=...apps.googleusercontent.com
cloud_client_secret_googledrive=GOCSPX-...
```

> **Google은 데스크톱 앱에도 시크릿을 요구합니다**(PKCE로 대체할 수 없습니다). 시크릿을 빼면 로그인 마지막 단계에서 조용히 실패합니다.
> 데스크톱 앱 유형은 리디렉션 URI를 따로 등록하지 않아도 루프백이 허용됩니다.

**테스트 모드의 대가**: 갱신 토큰이 **7일 후 만료**되어 재로그인이 필요합니다. 없애려면 동의 화면을 **프로덕션으로 게시**하세요(무료·즉시). 다만 `drive`는 제한된 범위라 인증을 받기 전까지 **100명 상한**은 남습니다.

---

### Dropbox — 앱 등록 절차

1. <https://www.dropbox.com/developers/apps> → **Create app**
2. **Choose an API**: Scoped access
3. **Type of access**: **Full Dropbox**
   > **App folder를 고르면 전용 폴더 하나만 보입니다.** 나중에 바꿀 수 없으니 주의하세요.
4. 이름을 정하고 생성
5. **Permissions** 탭에서 아래를 모두 체크하고 **Submit**
   - `files.metadata.read` · `files.metadata.write`
   - `files.content.read` · `files.content.write`
   - `account_info.read`
6. **Settings** 탭 → **Redirect URIs**에 **세 개를 모두** 추가:

   ```
   http://localhost:53682
   http://localhost:53683
   http://localhost:53684
   ```

   > **Dropbox는 등록값과 정확히 일치**해야 합니다(포트까지, 끝의 `/`도 붙이면 안 됩니다). Nexa Dir는 53682부터 차례로 시도하며, 세 개를 등록해 두면 포트가 사용 중이어도 연결됩니다.
7. **App key**와 **App secret**(Show)을 복사해 `settings.cfg`에 추가

**권한을 바꾼 뒤에는 반드시 연결을 해제하고 다시 연결**하세요. 기존 토큰에는 옛 권한이 박혀 있어 업로드가 거부됩니다.

## 한도와 제약

동봉된 기본 ID로 연결할 때의 한도입니다(2026-08 기준).

| 서비스 | 누가 쓸 수 있나 | 제약 |
| --- | --- | --- |
| **Dropbox** | 누구나 | 앱 전체 500명(50명 시점에 승인 신청 필요) |
| **OneDrive** | **개인 MS 계정 — 제한 없음** | **회사·학교 계정은 동의가 차단**될 수 있음 |
| **Google Drive** | 등록된 테스트 사용자 | 앱 전체 **100명**(누적) · 갱신 토큰 **7일** |

**회사·학교 계정에서 OneDrive 직접 연결이 막힐 때**는 두 가지 길이 있습니다.
1. **동기화 폴더를 링크**로 얹기(가장 간단 — 정책과 무관)
2. 회사 테넌트에 **직접 앱을 등록**해 그 ID를 `settings.cfg`에 넣기

**Google에서 "확인되지 않은 앱" 경고가 뜨거나 한도에 걸릴 때**는 위 절차로 자기 프로젝트를 만드는 것이 가장 확실합니다.

## 문제 해결

| 증상 | 원인·해결 |
| --- | --- |
| 로그인 후 "redirect_uri 불일치" | 콘솔에 등록한 리디렉션 URI가 다릅니다. OneDrive·Google은 `http://localhost`, Dropbox는 `http://localhost:53682`(끝에 `/` 없이) |
| Google 로그인이 마지막에 실패 | `cloud_client_secret_googledrive`가 없습니다 |
| 업로드·삭제가 거부됨 | 권한(scope)을 넓힌 뒤 **재연결**하지 않았습니다 |
| 목록이 비어 있음 | Dropbox를 **App folder**로 만들었거나, Google 범위가 `drive.file`입니다 |
| 며칠 뒤 다시 로그인하라고 함 | Google 테스트 모드의 7일 만료입니다 |
| 다른 PC에서 재로그인을 요구함 | 토큰이 DPAPI로 **이 PC에 묶여** 있습니다(정상 동작) |
| `불러오는 중…`이 사라지지 않음 | 새로 고침(`F5`) 후에도 남으면 `[!]`로 시작하는 행에 원인이 표시됩니다 |
| 연결이 목록에 없음 | 연결 직후 표시되지 않으면 `F5`로 새로 고침하세요 |
