# 플러그인 개발 (미리보기)

> ✅ **현재 상태(2026-07-27)**: 미리보기 플러그인 런타임 = **WASM(wasmi)**
> (ADR-0005 — 2026-07-26 Starlark에서 전환, 구판 서술은 git 이력).
> `data\plugins\*.wasm` 복사 = 동작. 심화 개발 가이드 → 저장소
> `docs/24-plugin-dev-guide.md`.

---

## 1. 개념 — 어떻게 동작하나

```
파일 선택 ─▶ 확장자 결정 ─▶ 공급자 결정 ─▶ nx_preview() 실행 ─▶ 표시
                              │                                  │
             ① 설정 preview_map(외부 재정의)        하단 도크 · 독립 창(F3/↗)
             ② 플러그인 선언(파일명 순)
             ③ 내장 폴백(이미지 → 텍스트)
```

- **플러그인 = `.wasm` 모듈 1개** — `data\plugins\`에 복사하고 앱을 재시작하면 끝
  (포터블은 exe 옆, 설치형은 `%LOCALAPPDATA%\NexaDir\data\plugins\`).
- **같은 파일이 모든 OS·아키텍처에서 동일 동작**(크로스플랫폼 단일 아티팩트).
- 개발 언어는 WASM으로 컴파일되는 것이면 무엇이든 가능하며 **러스트를 권장**합니다
  (`wasm32-unknown-unknown` 타깃).

### 왜 WASM인가 (설계 결정 — ADR-0005 / DR-7)

- **크로스플랫폼**: `.dll/.so/.dylib`처럼 OS별로 빌드·배포할 필요가 없습니다.
- **격리**: 연료(fuel) 상한·메모리 상한·샌드박스 — 플러그인 오류나 무한 루프가
  앱이나 다른 플러그인에 영향을 주지 않습니다.
- **예산**: wasmi(순수 러스트 인터프리터) 정적 링크 = exe **+1.68MB**(실측),
  JIT 런타임(수십 MB)은 exe ≤10MB 예산과 맞지 않아 채택하지 않았습니다.
- 이전 후보였던 Starlark는 실제 구축 결과 표현력·개발 체험 한계가 확인되어 교체
  했습니다(내장 폴백 안전망은 그대로).

## 2. 동작 범위

| 공급자 | 대상 | 동작 |
| --- | --- | --- |
| 플러그인(`.wasm`) | 선언 확장자 | `nx_preview()` 결과 표시(텍스트 라인 또는 이미지) |
| 내장 이미지 | png/jpg/jpeg/bmp/gif/ico/tif/tiff/webp | WIC 디코드·비율 유지 렌더 |
| 내장 텍스트(폴백) | 그 외 전부 | 첫 16KB·최대 200줄·탭 4칸·빈/이진/실패 안내 |

참조 구현 **markdown-viewer-wasm**(80KB)은 GitHub 근사 마크다운 렌더(제목·코드
블록·인용·표·목록)와 **Mermaid**(flowchart = 이미지 다이어그램, sequence = 텍스트
아트)를 제공합니다.

## 3. 계약 요약 (플러그인이 제공/사용하는 것)

- **export**: `nx_meta()` — `id\n표시명\next1,ext2`(적용 확장자 **기본값**) ·
  `nx_preview()` — 첫 줄 `lines`|`image` + 본문. 두 함수 모두 "선두 4바이트 길이 +
  UTF-8" 버퍼 포인터를 반환합니다.
- **호스트 API**(이것 외 I/O 차단): `read_text(ptr,cap)` — **미리보기 대상 파일만**
  (256KB 상한) · `render_svg(...)` — SVG를 이미지로 래스터(다이어그램용) ·
  `is_dark()` — 테마 신호.
- **표시 태그**: 라인 앞에 종류 태그를 붙이면 독립 창이 제목·코드·인용·표·이미지를
  구분해 렌더합니다(자세한 표는 개발 가이드 §3).

## 4. 사용자 설정

- **설정 → 플러그인**: 설치된 플러그인 목록과 **사용 여부 체크**(해제 = 내장
  미리보기로 대체·즉시 적용·재시작 후에도 유지).
- **확장자 재지정**: `settings.cfg`의 `preview_map=md:markdown|txt:markdown` 형식 —
  플러그인이 선언한 기본 확장자를 사용자가 덮어씁니다.
- **우선순위**: 설정(`preview_map`) > 플러그인 선언(파일명 순) > 내장 폴백.

## 5. 만들기 → 배포 (요약)

```
rustup target add wasm32-unknown-unknown          # 1회
cargo build --release --target wasm32-unknown-unknown
copy target\wasm32-unknown-unknown\release\my_viewer.wasm  <NexaDir>\data\plugins\
```

시작 템플릿 = `samples/markdown-viewer-wasm`(Markdown) 또는
`samples/archive-viewer-wasm`(압축 목록 — ABI v2). 배포물은 `.wasm` 하나이며,
사용자는 복사 + 재시작만 하면 됩니다. 제거 = 파일 삭제 후 재시작(또는 설정에서 체크 해제).

## 5-1. 동봉 플러그인 — 어디에 있고 어떻게 바꾸나

`markdown.wasm`(Markdown·Mermaid)과 `archive.wasm`(ISO·ar·cpio 압축 목록)은
**배포에 함께 들어 있습니다**. 앱이 읽는 위치는 두 곳입니다.

| 순위 | 위치 | 성격 |
| --- | --- | --- |
| ① | `data\plugins\` (포터블 = exe 옆 · 설치형 = `%LOCALAPPDATA%\NexaDir\data\plugins\`) | 사용자가 넣는 자리 |
| ② | exe 옆 `plugins\` | 배포 동봉분(읽기 전용) |

**같은 이름(id)이면 ①이 이깁니다** — 동봉본을 직접 고친 빌드로 대체하려면 ①에 넣으면
되고, 동봉 파일 자체는 건드리지 않아도 됩니다. 단일 exe만 받았다면 릴리스의
`NexaDir-Plugins-<버전>.zip`을 exe 옆에 풀면 같은 상태가 됩니다.

**저장소에서 두 플러그인을 고칠 때**(개발자):

```powershell
pwsh scripts/build-plugins.ps1          # 두 샘플 빌드 + samples/*/dist 갱신
cargo test -p nexa-app preview::sample  # 동봉본 E2E 검증
```

릴리스는 태그의 소스로 다시 빌드해 포터블 zip·설치본·플러그인 zip에 싣습니다
(절차 = `docs/18 §3-1` · 배포 형태 = `docs/21 §5-2`).
