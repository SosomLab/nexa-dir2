## 글꼴 폴백 체인 실적용 — "두부 방지"(사용자 요청)

**요청**: "폰트 다중 설정 기능은 있지만, 두부 방지를 위해서 폰트 Fallback 기능 구현해줘".

**실측**: 쉼표 목록 = 폴백 체인 규약([fontbox](../../crates/nexa-app/src/ctl/fontbox.rs) 선택 규칙·
[config](../../crates/nexa-app/src/config.rs) 주석)은 **터미널(X-3)에서만** `IDWriteFontFallback`으로
살아 있었다. 나머지 경로는 체인 **문자열 전체**를 패밀리/얼굴 이름으로 넘기고 있었다 —
DirectWrite UI 슬롯(기본/목록/상태바)은 존재하지 않는 패밀리 취급, GDI(`CreateFontW` — 대화상자·
설정 창 제목·about·미리보기)는 매칭 실패로 기본 글꼴 대체. 즉 **2순위 이후는 물론 1순위조차
적용되지 않는 상태**였고, 체인의 기호/이모지 글꼴은 아무 데도 쓰이지 않았다.

**구현**(`feat(font)` — [fontchain.rs](../../crates/nexa-app/src/fontchain.rs) 신설):
- `families`/`first_installed`/`fallbacks` — 설치 글꼴 목록은 fontbox의 `EnumFontFamiliesExW`
  1회 열거 재사용. **1순위 = 설치된 첫 패밀리**, 폴백 = 나머지 설치 패밀리(순서 보존).
- **DirectWrite**([dw.rs](../../crates/nexa-app/src/dw.rs)): 슬롯 3종도 1순위 패밀리로 포맷 생성 +
  `build_fallback`(터미널 빌더를 공용화 — 전 유니코드 범위에 체인 순서 매핑 → 시스템 폴백 연결)
  → `layout_for`에서 슬롯별 `SetFontFallback`. 레이아웃 캐시는 스타일 키라 그대로.
- **GDI 글리프 단위 폴백** `GdiChain`(미리보기 창 [previewwnd.rs](../../crates/nexa-app/src/previewwnd.rs)):
  `GetGlyphIndicesW(GGI_MARK_NONEXISTING_GLYPHS)`로 1순위 미보유 문자를 찾아 체인의 다음 글꼴로
  **런을 나눠** `ExtTextOutW`. 측정(`offsets`)도 같은 런 규칙이라 선택 경계가 그리기와 일치.
  비BMP(서러게이트)는 판정 불가라 1순위에 두고, 어느 글꼴에도 없는 문자도 1순위 = OS 글꼴 연결
  (FontLink)에 마지막 기회. 본문(Segoe UI) 체인의 폴백 = 콘솔 체인의 나머지(사용자가 체인에
  넣은 기호 글꼴이 본문에도 적용).
- **GDI 대화상자·제목 글꼴**: 설치된 첫 패밀리로 생성(1순위 결함 정정). 네이티브 컨트롤
  (STATIC/EDIT)은 글리프 개입이 불가 — 한중일은 OS 연결로 충분하고, 그 밖은 한계로 명시.

## 설정 창 본문 스크롤 재구축 — 깜박임·트랙패드·오버레이 스크롤바(사용자 QA 3건 + 추가 지시 2건)

**증상(사용자 스크린샷)**: ① 우측 본문을 휠로 스크롤할 때마다 **창 전체가 깜박임** ② 트랙패드로
천천히 밀면 **픽셀 단위 스크롤이 안 됨** ③ 스크롤바가 없음. 작업 중 추가 지시 2건: 스크롤바는
네이티브가 아니라 **파일 그리드 방식**(반투명·스크롤 중만 표시 후 사라짐·마우스 오버 시 두꺼움)
으로 · 트랙패드 미세 스크롤 시 **스크롤바 자체가 블링크**.

**진범**: [prefs.rs](../../crates/nexa-app/src/prefs.rs)의 본문은 실제 Win32 자식 컨트롤 묶음인데
휠 한 번마다 `harvest → rebuild`(**전 컨트롤 파괴·재생성**)로 오프셋만 바꿔 다시 만들고 있었다
(QA 07-15의 최소 구현). `InvalidateRect(창 전체, erase=true)`까지 붙어 사이드바도 같이 지워졌다.
트랙패드는 `delta / 120 * 48`이라 **120 미만 델타가 0으로 버려졌다**.

**구조**(`f5b484a`):
- **본문 컨테이너 `NexaPrefsPane`** 신설(구분선 우측 전체·WS_CLIPCHILDREN·WS_EX_CONTROLPARENT).
  항목 컨트롤의 부모가 창 → 컨테이너로 바뀌고, 자식 통지(WM_COMMAND·CTLCOLOR*·DRAWITEM·
  MEASUREITEM·NOTIFY)는 **메인 창으로 그대로 전달** — 기존 핸들러 무변경.
- **스크롤 = 자식 이동**: 컨테이너 직속 자식 전부를 `BeginDeferWindowPos`로 한 번에 `-dy` 이동.
  이동은 비트 복사라 자식 재도장이 없고 부모는 드러난 영역만 소거 → 깜박임 소멸. 편집 중 값·
  포커스·캐럿 보존(재구성이 없으니 QA 07-16의 harvest 재진입 결함 경로 자체가 사라짐).
- **휠 잔량 누적**: `wheel_rem`에 1/120 노치 단위로 누적, `px = total × 60 / 120`(노치당 60px —
  ÷2라 잔량 계산이 정확). 트랙패드 델타 30 × 3 = **45px 픽셀 단위** 확인.
- **오버레이 스크롤바**(그리드 07-18 규약 계승 — [ctl/grid.rs](../../crates/nexa-app/src/ctl/grid.rs)·
  [bulkrename NexaCardHost](../../crates/nexa-app/src/bulkrename.rs)와 같은 위치·두께 6/10·최소 24·
  900ms 유지) + 이번 확장: **반투명**(GDI+ 알파 120 — `GdipCtx::fill_round_rect_alpha` 신설) ·
  **단계 페이드**(40ms 틱 −24) · **호버 시 두꺼움**(TrackMouseEvent·알파 210·페이드 보류) ·
  드래그 = 트랙 표시 · 트랙 클릭 = 페이지. 자식이 덮지 않는 우측 PAD 스트립에 그린다.
- **블링크 해소**: 컨테이너 WM_PAINT를 **rcPaint 크기 메모리 DC 더블버퍼**로, WM_ERASEBKGND는
  1 반환(기본 소거 차단). 미세 스크롤마다 흰색 소거 → 썸 재도장이 눈에 보이던 것.

**실측 교훈 하나**: 처음엔 컨테이너에 **WS_EX_COMPOSITED**(자식 일괄 더블버퍼)를 줬는데
**합성 DC 위에서 GDI+ 알파 썸이 전혀 그려지지 않았다**(스크롤·호버 로직은 동작·화면만 백지).
빼자 즉시 표시. DeferWindowPos 비트 복사만으로 깜박임은 충분히 잡히므로 COMPOSITED 없이 확정.

**기존 구현 대조(사용자 질문 — "파일 그리드에 적용된 방식도 확인")**: NxGrid·NexaCardHost의
