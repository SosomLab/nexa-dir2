## Chocolatey 승인 → `0.18.1` 두 패키지 제출(사용자 지시 — "choco 승인됨·현재 버전 재배포")

**실측으로 확인한 것부터.**

- **Chocolatey 2종 = 승인 완료**: OData `FindPackagesById()` 조회에서 `nexa-dir`·
  `nexa-dir.portable` **둘 다 `0.8.1` / `PackageStatus: Approved`**. 07-20 바이러스 스캔
  플래그 이후 **44일** 만의 해소(모더레이터 면제) — 미승인분은 공개 피드에 안 나오므로
  **OData에 잡힌다는 것 자체가 승인의 증거**다.
- **winget 2채널 = 이미 최신과 동기**: `0.18.1` PR 2건([#423330](https://github.com/microsoft/winget-pkgs/pull/423330)·
  [#423331](https://github.com/microsoft/winget-pkgs/pull/423331))이 **08-24 제출 ~1시간 만에 둘 다 MERGED**.
  카탈로그 디렉터리 실측도 두 패키지 모두 `0.18.1` 상주 = **제출할 것이 없다**
  (열려 있는 우리 PR은 NexaBeep 것뿐 — 다른 제품이라 이 채널 판정과 무관).
- **저장소 최신화**: `git fetch --all --tags` 후 `main` = `origin/main` **0/0·트리 clean**.

**따라서 이번 "재배포"의 실체는 choco 한 채널**이다 — [채널 제출 규칙](../21-distribution.md#릴리스-시-채널-제출-규칙-2026-08-23--사용자-지시상시-규칙)
그대로: 대기 중인 버전이 사라진 채널(choco)에 **그 시점 최신 버전만**(0.9.0~0.18.0 중간 버전은
생략) 올리고, 대기 없이 이미 동기인 채널(winget)은 손대지 않는다.

**빌드는 하지 않았다** — 태그 `0.18.1`(`2287a66`) 이후 main의 7커밋은 **docs 4 · choco 패키징
fix 2 · ci 1**뿐이고 `crates/`·`samples/`·`Cargo.*`는 **한 줄도 바뀌지 않았다**. 즉 배포 대상
바이너리는 이미 릴리스에 있는 것과 동일하며, 재빌드는 같은 exe를 다른 해시로 만들 뿐
(무서명 새 해시 = Defender ML 프리밸런스 0 재발 — [12 §4-2](../12-packaging-single-exe.md))이라
**해로울 뿐 득이 없다**.

**절차**:

1. **`CHOCO_PUSH=true` 등록**(`gh variable set` — 07-21 도입 게이트의 설계된 재개 조건.
   "승인 시 변수 등록으로 재개, 코드 무변"을 그대로 이행).
2. **`resubmit-chocolatey` 워크플로 dispatch**(`version=0.18.1`, `confirm=yes`) — 08-31 상설화한
   경로가 여기서 처음 제 역할을 했다. **빌드 없이 릴리스 자산을 내려받아** 해시 계산 →
   ps1 치환 → `choco pack` → `choco push`. 태그를 건드리지 않으므로 Release·해시 불변.
   - 이 경로를 고른 이유가 하나 더 있다: **모더레이터 지적 반영분(`da0d5bd`·`6a9c0eb` —
     VERIFICATION.txt 제거·`owners=kiros33`·ps1 UTF-8 BOM·제거 스크립트 파스 오류)이
     태그에는 없고 main에만 있다.** release.yml 재실행은 태그 소스를 쓰므로 **낡은 패키징으로
     되돌아갔을 것**이다. dispatch는 main을 체크아웃한다.
3. **결과**([run 33578690160](https://github.com/SosomLab/nexa-dir2/actions/runs/33578690160), 23초):
   두 nupkg 팩·push 모두 성공. 계산된 해시 = 릴리스 `SHA256SUMS.txt`와 **일치**
   (설치형 `89947fb5…`·포터블 `8d9dbd35…`).
4. **제출 확인**: `Packages(Id='…',Version='0.18.1')` 직접 조회 = 두 패키지 모두
   **`PackageStatus: Submitted`**(검수 큐 진입 — `FindPackagesById()`는 승인분만 반환하므로
   여전히 0.8.1만 보이는 것이 정상).
