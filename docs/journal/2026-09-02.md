## main 적색 발견·복구 — `Secret` 소거 테스트가 해제된 메모리를 읽고 있었다

push 직후 CI를 확인하다 **main이 08-24부터 붉었다**는 것을 발견했다(`core (ubuntu)`·
`core (macos)` 실패 · `windows` 성공). 9일 · 8개 커밋 동안 아무도 못 봤다 —
**08-02와 같은 사각지대의 거울상**이다. 그때는 Windows만 돌려 비Windows 컴파일이 깨진 것을
놓쳤고, 이번엔 **Windows에서만 우연히 통과하는 테스트**를 놓쳤다.

**원인**(`nexa-core::secret::tests::clone_is_independent_and_drop_zeroizes`):

```rust
let raw = c.expose().as_ptr();
drop(c);
let seen = unsafe { std::slice::from_raw_parts(raw, len) };   // ← 해제된 메모리를 읽는다
assert!(seen.iter().all(|&b| b == 0), "Drop 소거");
```

**해제된 블록을 다시 읽는 것 자체가 UB**다. glibc·macOS 할당자는 free 직후 그 블록
앞머리에 **free 리스트 포인터를 써 넣기 때문에** `abc`(3바이트) 자리가 0이 아니게 되고,
Windows 힙은 마침 그러지 않아 통과했다. 즉 **소거 구현은 처음부터 옳았고 검사 방식이
틀렸다** — 기능 결함이 아니라 테스트 결함이다.

**수정**: `Drop` 본문을 `Secret::zeroize()`로 분리하고, 테스트는 **살아 있는 버퍼에서**
같은 경로를 호출해 0을 확인한다(사본 독립성 단언은 유지). 계약은 그대로이고 UB만 사라진다.

- 게이트: `cargo test -p nexa-core` **6 green** · `cargo clippy -p nexa-core --all-targets -D warnings` 0 ·
  `cargo check -p nexa-core --all-targets --target x86_64-unknown-linux-gnu` green(**깨진 쪽 타깃으로 직접**).
- 교훈: [18 §2·§4](../18-build-and-test.md)의 "비Windows도 검사"는 **`cargo check`만으로는
  부족**하다 — 이번 건은 컴파일이 아니라 **런타임 동작 차이**였다. 로컬에서 잡으려면
  비Windows에서 `cargo test`가 필요하고, 그게 안 되면 **push 후 CI 3잡을 실제로 확인**하는
  절차가 유일한 그물이다(이번에 9일이나 걸린 이유가 그 확인 누락이다).
