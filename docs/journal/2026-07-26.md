## 리네임 재클릭 결함 픽스 + Mermaid 이미지 수준 검토 (사용자 QA·질의 — 5차, 같은 브랜치)

- **픽스**(`ef9de84` — 사용자 QA): 리네임 중 다른 행을 클릭해 리네임을 끝낸 뒤,
  그 행 재클릭이 리네임에 들어가지 않고 **한 번 더** 필요하던 결함.
  진범 = 슬로우클릭의 프레스 시점 행 히트가 `is_renaming()` **전체 가드**로
  None → 취소 클릭이 `slow_click` 이력을 소실. 수정 = 가드를 **편집 필드 안
  클릭만**으로 축소(`rows.rename_field_hit` 신설) + 리네임을 끝낸 클릭은
  시드만 하고 예약은 안 함(`was_renaming` 가드 — 취소 클릭이 곧바로 새
  리네임을 잡는 부작용 방지). 218 green·clippy 0.
- **검토 ③ 현 플러그인 구조에서 Mermaid 이미지 수준 가능?**(사용자 질의):
  **가능 — 단 호스트 확장 필요.** Starlark 단독으론 불가(그리기/파일 API 없음 —
  샌드박스 설계)지만, 계약에 **`{"draw": [명령]}` 반환 형식을 추가**하면
  플러그인의 기존 레이아웃 엔진을 좌표 출력으로 전환하고 **호스트 GDI+
  (gdipctx — 이미 보유한 인박스 AA 래스터라이저)** 가 상자·곡선 화살표·색을
  이미지 품질로 렌더할 수 있다(exe 증가 0·크레이트 0·라이선스 무관·샌드박스
  유지). 대안 B = 호스트 내장 `mermaid` 래스터 헬퍼(플러그인은 {"image"}로
  수신). 한계 = 자동 배치 품질은 mermaid.js(dagre)보다 단순(전형적 flowchart/
  sequence는 충분·복잡 그래프는 열세). **완전 동일 품질 = 웹뷰 필요**(DR-1/B3
  상충 — 4차 검토 결론 유지, 그 품질은 Nexa Markdown Viewer 연동이 지름길).
  방향 결정 대기.
