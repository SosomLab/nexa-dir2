- **`README.md`는 발행 제외** — 이 파일은 위키 페이지가 아니라 **`docs/wiki/` 폴더
  자체의 설명서**(발행 절차 안내)다. 그대로 올렸으면 위키에 엉뚱한 `README` 페이지가
  생겼을 것이다. 발행된 위키에 원래 없다는 점이 근거였다.
- **"미발행 15건"은 과대 집계였다** — 파일 해시로 비교해 15건이 나왔는데, git에
  스테이징하니 **실제 내용 차이는 5건**이고 나머지 10건은 **CRLF/LF 줄바꿈 차이**였다.
  해시 비교는 줄바꿈을 구분하므로 발행 판단에는 부적절하다 — 다음부터는 `git diff --stat`
  으로 센다.
- 발행 후 소스를 다시 덮어써 `git status`가 **빈 출력**임을 확인(로컬 소스 ≡ 발행본).

## X-40 외부·클라우드 변경 무갱신 해소 + X-41 도구 모음 24×24 (사용자 요청 2건 — `fix/x40-refresh-probe` 2커밋, 실기 QA 대기)

### X-40 — "갱신 버튼을 눌러야 한다"의 원인 4건

사용자 보고: *"외부에서, 특히 클라우드에서 파일이 저장되거나 동기화된 경우 파일 목록
갱신이 되지 않아서 직접 갱신 버튼을 눌러야 하는 경우가 종종 발생"*. 07-31 안정성 감사가
**watcher 죽음**을 잡았고 08-02에도 남아 있던 이 증상을, 이번엔 통지 경로 전체를 훑어
원인을 넷으로 갈랐다. **공통 뿌리 = 갱신 계기가 `ReadDirectoryChangesW` 통지 하나뿐**이었다.

| # | 원인 | 왜 07-31 수정으로 안 잡혔나 |
| --- | --- | --- |
| 1 | **활성화 갱신 계기 부재** — `WM_ACTIVATEAPP` 핸들러가 **아예 없었다**(grep 실측) | 통지 유실은 조용하다. 밖에서 저장하고 돌아와도 재열거를 시킬 자리가 없어 F5 전까지 낡은 채였다(탐색기는 활성화 시 갱신한다) |
| 2 | **통지가 오지 않는 경로에 폴백 부재** — RDCW는 로컬 NTFS 규약. 클라우드 가상 드라이브(Google Drive DriveFS 등)·네트워크는 **구독이 성공해도 통지가 안 올 수 있다** | 그때 watcher는 **죽은 게 아니라 조용한** 것이라 `is_alive()`는 계속 true — 07-31의 생존 자가 치유가 원리적으로 못 잡는 사각지대 |
| 3 | **디바운스 무한 연기** — `SetTimer`는 같은 ID 재무장 시 만료를 **미룬다**. 동기화가 300ms보다 촘촘히 변경을 쏟으면 타이머가 계속 밀려 **동기화가 끝날 때까지 한 번도 재로드되지 않는다** | 코얼레싱이 의도대로 동작한 결과라 결함으로 안 보였다. 사용자 보고의 "동기화된 경우"가 정확히 이 경로 |
| 4 | **죽은 watcher 치유가 사용자 상호작용 의존** — `sync_watchers`는 `update_status`에서만 호출된다 | 07-31이 `is_alive` **관측**은 만들었지만 **호출 계기**는 안 만들었다. 유휴로 폴더를 보는 동안 죽으면 되살릴 자리가 없다(자니터는 트림만 하고, 유휴 트림 후엔 자기 타이머까지 끈다) |

**해결 — 통지에 의존하지 않는 두 번째 계기를 만든다**

- **[fsprobe.rs](../../crates/nexa-app/src/fsprobe.rs) 신설**(저비용 폴더 서명):
  **1단계 = 폴더 자신의 mtime**(O(1) — NTFS는 항목 추가·삭제·이름 변경 시 디렉터리
  엔트리를 갱신하므로 "파일이 생겼다"는 이것만으로 잡힌다) + **2단계 = 상한
  `SCAN_CAP`(4096) 내 1회 열거**(항목 수·총 바이트·최신 자식 mtime — 1단계가 못 잡는
  **같은 이름 덮어쓰기**를 잡는다). 상한 초과 폴더는 2단계를 포기해 폴링 비용이 터지지
  않게 한다. `std::fs`만 쓰므로 **전 플랫폼 컴파일·테스트**(08-02 비Windows 교훈).
- **`WM_ACTIVATEAPP` + 최소화 복원 → `refresh_on_return`**: 죽은 watcher 재구독 →
  즉시 프로브 → 폴링 재개. **변경이 없으면 재로드도 없다**(프로브 비교가 게이트).
- **`TIMER_FSPOLL` 3s 폴링** — **창이 활성일 때만**. 비활성·최소화 시 `KillTimer`로
  **유휴 백그라운드 0% 규율(DR-2)을 유지**하고, 안 보는 동안의 낡음은 다음 활성화의
  즉시 프로브가 해소한다. 틱마다 `sync_watchers`도 부르므로 원인 4도 함께 닫힌다.
- **`WATCH_MAX_MS` 1s 연장 상한** — 첫 통지로부터 1초를 넘기면 재무장하지 않는다.
  이미 걸린 타이머가 그대로 만료되므로 **폭주 중에도 최대 1.3초 안에 1회는 갱신**된다.

설계상 주의로 남긴 것 둘: ① **재로드 직후 기준선 재프로브** — 안 하면 방금 반영한
변경으로 폴링이 다시 무장해 진동한다 ② **`WM_SIZE`는 리사이즈 드래그 내내 오므로
최소화 복원만 갱신 계기로** 삼았다(무조건 프로브하면 드래그마다 폴더를 재열거한다.
`note_activity`가 `trimmed`를 지우므로 **호출 전에** 읽는다).

**검증** — 신규 테스트 5(추가 감지·내용만 변경 감지·무변경 안정·가상 루트 `None`·
디바운스 상한). **106 green(nexa-app)·78(nexa-gui)·비Windows check 통과**.
release 기동 후 패널이 보는 폴더에 파일을 만들자 **버튼 없이 목록에 나타남**을 실기
확인(이 경로는 기존 watcher로도 잡히므로 **무회귀 확인**이지 폴백 검증은 아니다 —
클라우드 실검증은 사용자 QA). 폴링 비용은 7항목 폴더에서 **10초간 CPU 0.0ms**로
측정 한계 미만(대형 폴더는 `SCAN_CAP`이 상한). B2 **3.66MB** · B3 통과.
