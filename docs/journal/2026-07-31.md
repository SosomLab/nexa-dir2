## 연 프로그램이 뒤에 숨는 결함 — 포그라운드 권한 양도 (사용자 QA — `fix/foreground-activation`)

### 증상 (사용자 보고)

파워포인트 등의 파일을 더블클릭하면 **문서는 열리는데 창이 활성화되지 않고 뒤에 숨는다.**
이미 열려 있던 파일이든 새로 여는 파일이든 발생.

### 원인 — Windows 포그라운드 잠금(foreground lock)

Windows는 **포그라운드 창을 가진 프로세스만** `SetForegroundWindow`를 허용한다.
`ShellExecute`·`IContextMenu::InvokeCommand`는 연결 프로그램이 **이미 떠 있으면**
새 프로세스를 만들지 않고 **DDE/COM으로 기존 프로세스에 열기를 위임**한다
(PowerPoint 등 Office가 대표적). 그 프로세스는 우리가 만든 자식이 아니므로 포그라운드
권한을 물려받지 못하고, `SetForegroundWindow`가 거부되어 **작업 표시줄만 깜빡이고
창은 뒤에 남는다**. 탐색기는 호출 직전 `AllowSetForegroundWindow`로 권한을 넘겨 이를 피한다.

"새로 여는 파일에서도 발생"하는 이유 = Office는 단일 인스턴스 모델이라, 이미 앱이
떠 있으면 **새 문서도 기존 프로세스가 연다**(= 위임 경로 동일).

### 수정 — `win::allow_foreground_handoff()` 신설 + 실행 위임 4개소 적용

`AllowSetForegroundWindow(ASFW_ANY)`를 호출 **직전**에 부른다(반환값 무시 — 호출자가
포그라운드가 아니면 실패하지만, 그 경우는 애초에 우리가 창을 가리지 않는다).

| 파일 | 지점 | 경로 |
| --- | --- | --- |
| `win.rs` | `shell_open` | 파일 더블클릭·Enter·Alt+↓ (**주 증상**) |
| `shellmenu.rs` | `invoke` | 셸 우클릭 "열기"·"연결 프로그램"·"편집" |
| `launcher.rs` | `launch` | 퀵 런처 바 |
| `about.rs` | 링크 클릭 | 기본 브라우저 URL 열기 |

`recycle.rs`의 `InvokeCommand`는 삭제 작업이라 포그라운드와 무관 — 제외.

### 결정 — zip 자산 **추가**(사용자 지시: 기존 Release 구성 유지)

| 단계 | zip 효과 |
| --- | --- |
| 브라우저 다운로드 차단(실제 증상) | ✅ **해소** — exe 확장자 평판 필터를 타지 않음 |
| 실행 시 SmartScreen 경고 | ❌ 남음 — Explorer·WinRAR·7-Zip 22.00+ 는 압축 해제 시 MOTW 전파 |
| Defender 검사 · Smart App Control | ❌ 무관 |

- 기존 exe 자산은 **그대로 유지** — winget·choco 매니페스트가 URL+SHA256으로
  직접 참조하므로 교체하면 3채널이 동시에 깨진다. zip은 덧붙이기만.
- **포터블 zip 우선 안내**. 설치형 zip은 압축을 풀어도 UAC "알 수 없는 게시자"
  프롬프트가 추가되고 설치 프로그램 자체가 Defender 휴리스틱에 더 잘 걸린다.

### 구현 (release.yml — 스텝 2개 신설)

- **`ZIP 자산 추가`**: `README.txt`(무서명 경고 예고 + [추가 정보]>[실행] 안내 +
  `Get-FileHash` 대조법 · 한/영 · UTF-8 BOM) 생성 → `Compress-Archive`로
  `NexaDir-<버전>-win-x64.zip`(포터블+README) ·
  `NexaDir-Setup-<버전>.zip`(설치형+README) 2종.
- **`SHA256SUMS.txt`**: 자산 4종(exe 2 + zip 2) 체크섬 — README가 안내하는 대조본.
  ascii 인코딩·`<hash>  <파일명>` 표준 형식.
- `upload-artifact` path + `action-gh-release` files에 `NexaDir-*.zip`·
  `SHA256SUMS.txt` 추가. **태그 push에서만 동작**(`if: github.ref_type == 'tag'`).
- 결과 Release 자산 = **exe 2 + zip 2 + SHA256SUMS.txt = 5종**.

### 함정 — YAML 블록 스칼라 × PowerShell here-string

`run: |` 안에서 here-string(`@" ... "@`)은 **종료자가 컬럼 0**이어야 해 YAML 들여쓰기
블록을 이탈시킨다(파서 오류 14건). **문자열 배열 + `Set-Content`** 로 우회 — 같은
결과에 들여쓰기 유지. 동일 함정이 재발할 수 있어 워크플로에 주석으로 남김.
