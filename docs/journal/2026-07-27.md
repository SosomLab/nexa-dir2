## 항목 우클릭 "새로 만들기" + 생성 후 인라인 리네임 (사용자 요청 — `feat/ctx-new-menu` `e915506`)

- **요구 3건**: ① 파일/폴더 **항목** 우클릭에도 새로 만들기 표시(파일=부모 폴더·
  폴더=그 폴더의 빈 영역 우클릭과 동일 동작) ② 폴더만이 아니라 **파일 템플릿
  메뉴도 동일하게**(일관성) ③ 새 폴더 생성 후 **이름바꾸기 모드 즉시 진입**.
- **검토**: 셸 규칙상 New(ShellNew)는 **배경 메뉴 전용**(`CreateViewObject`) —
  항목 메뉴(`GetUIObjectOf`)에는 절대 안 나옴(탐색기 동일) → 기본 기능 불가,
  직접 병합 필요. 방식 3안 비교 후 사용자 확정 = **셸 New 확장(CLSID_NewMenu)
  직접 호스팅**(배경 메뉴와 100% 동일한 템플릿 목록·OS 아이콘) · 다중 선택 시
  **숨김**(대상 폴더 모호 — pasteInto와 같은 규칙).
- **구현**(shellmenu.rs):
  - `NewSpec`(대상 폴더+라벨) → `attach_new_menu`: `CoCreateInstance(CLSID_NewMenu)`
    → `IShellExtInit::Initialize(대상 폴더 PIDL)` → `QueryContextMenu`로 하단
    구분자 아래 서브메뉴 병합. **전용 대역 0x7000~0x7FFF**(셸 1~0x6FFF로 축소·
    고유 0x8000+ 불변). 라벨은 앱 언어 추종 `ctx.new`(QA 07-14 규약·lang 3종).
  - 포워딩 `ACTIVE` 단일쌍 → **Vec**(항목 ICM + New ICM 공존 — 서브메뉴 lazy
    채움 `WM_INITMENUPOPUP` 포워딩·MENUCHAR는 첫 유효 응답). 실패 시 조용히
    생략(메뉴는 정상 표시).
  - **생성 감지 = 전후 diff**: 셸 invoke는 생성 파일명을 반환하지 않음(탐색기는
    IFolderView 사이트 통보 — 우리는 뷰 미노출) → invoke 전 `dir_names` 스냅샷,
    후 diff **정확히 1개**일 때만 `Outcome::Created(경로)`(다건=압축 해제 등
    오탐 방지). New 대역=20ms×10 재시도·배경 메뉴=셸 실행 전반 휴리스틱(20ms×2 —
    붙여넣기는 기가로채라 실질 커버는 새로 만들기).
- **win.rs**: `create_new` 후반부를 `focus_created_and_rename`으로 공용화 —
  재로드→캐럿→`begin_rename`(앱 새 폴더/파일 Ctrl+Shift+N은 **기존에 이미 진입**
  — 요구 ③의 실제 갭은 셸 경로였음). 접힌 폴더 안 생성(폴더 항목 New)은
  `hover_expand`로 부모 펼침 후 진입·행 미발견 시 조용히 생략. 항목·배경 메뉴
  모두 `Outcome::Created` → 이 헬퍼.
- **설정**: `ctx_menu_order` row 블록에 `new` 키(표시 제어 — 위치는 하단 고정
  섹션. 구 저장값엔 보충 삽입) + 설정 창 라벨(`ctxm_label`). 왕복 테스트 기대값 갱신.
- 실측: **217 green**·clippy 0·release 3.34MB(≤10). **실기 QA 대기**: 항목 New
  전 템플릿 생성·리네임 진입·배경 메뉴 리네임 진입·다중 선택 숨김·설정 숨김.
