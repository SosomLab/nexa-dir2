## X-35 휴지통 삭제 실패 무통지 — 분석·설계 확정 (사용자 보고 — 코드 무수정)

- **증상**: 낙관적 숨김+워커 삭제(X-30 ⑥) 중 **열린 파일이라 삭제 실패**하면
  잠시 후 행이 재출현하는데 **아무 통지 없이** 취소 상태로 돌아옴.
- **분석 — 결함 4건**([win.rs](../crates/nexa-app/src/win.rs) `do_delete`/`on_delete_message`):
  - D1 실패 통지가 타이틀 바 한 줄뿐(FOF_SILENT+워커+hwnd 미지정 = 셸 오류 창도 없음)
  - D2 SHFileOperationW **배치 1콜 반환값 1비트** → 항목별 결과 소실(1개 잠김=전부 실패 집계)
  - D3 부분 성공 시 **undo 미기록**(ok_flag=false면 DeleteBatchOp 안 쌓음)
  - D4 watcher 디바운스 재로드에 `pending_delete` 가드 없음 → 진행 중 조기 재출현 가능
- **원본 대비 회귀 3건 확인**(SSOT `../nexa-dir` MainWindow.DeletePaths·FileOps):
  원본은 항목별 격리·성공분만 부분 undo·`OnlyErrorDialogs`(OS 오류 창)+상태바
  `del.partialFail` — 전부 워커 이관·배치화 과정에서 상실. 단 원본은 UI 동기라
  3~4초 프리즈를 가졌으므로 원본 복원이 아닌 재설계 필요.
- **설계 확정**(후보 4안 비교 — 사용자 결정 2건 포함):
  - **레이어드 P+B 채택**: ① **사전 잠금 프로브**(사용자 제안 — 파일별
    `CreateFileW(DELETE, 공유 全)` µs 프로브·폴더는 자기 자신만[하위 재귀 비용 회피])
    ② 잠긴 항목 발견 시 **모달로 묻고 선택**(목록+"다른 프로그램에서 사용 중"+
    [건너뛰고 삭제]/[취소] — 잠긴 항목은 숨기지 않음) ③ 워커 배치 후 **`exists()`
    diff 백스톱**(TOCTOU·폴더 하위 잠김·기타 실패 포착) ④ 실패 시 **모달+
    [다시 시도]**(실패분만 재진입)+재로드 후 실패 항목 자동 선택·캐럿
    ⑤ **성공분만 부분 undo**(원본 규약 복원) ⑥ **watcher 가드**(pending_delete 중
    디바운스 지연) ⑦ lang `del.partialFail`·잠김 안내 키 추가.
  - 기각: 항목별 SHFileOperationW 루프(호출당 셸 고정 비용×N — 대량 저하) ·
    사전 프로브 단독(TOCTOU·폴더 한계로 백스톱 필수).
  - 보류: **IFileOperation 전환(A안)** — 항목별 HRESULT sink·진행률 확장 여지.
    구현량 커서 후속 재검토(원본 문서 기존 재검토 항목과 병기).
