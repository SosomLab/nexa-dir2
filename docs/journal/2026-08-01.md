## X-37 7~13차 — Google 완성·진행률·UX·Dropbox 실사용 (사용자 QA 연속 17건)

6차까지가 "기능을 놓는" 단계였다면, 이후는 **실기 QA가 결함을 뽑아낸** 단계다.
사용자 보고 17건이 전부 진짜 결함이었고, 그중 다수는 **한 증상 = 두 원인**이었다.

### Google Drive 연결 완성 (`175b5e1`·`2e44a02`·`976435e`·`ee45bcf`)

- 사용자 콘솔 `drive.file` scope 발견 → **탐색기로 성립 불가**(앱이 만든 파일만 열거)
  → `drive` 전체로. 게시 상태 "테스트"면 CASA 없이 동작하나 **refresh 7일 만료**가 대가.
- **연결이 조용히 실패**하던 원인 = Google은 데스크톱 앱에도 `client_secret`을 요구
  (PKCE로 대체 불가). `Service::default_client_secret` 신설 후 동봉(사용자 결정 —
  네이티브 앱의 이 값은 Google 공식 문서가 "비밀이 아니다"라고 명시).
- 계정 표시명은 `oauth2/userinfo` 대신 **Drive `about?fields=user`** — 이미 가진
  scope만으로 이메일을 얻어 콘솔 설정을 늘리지 않는다.
- **인증 실패가 타이틀 바에만 뜨던 것**을 모달로 승격(사용자가 실패를 놓쳤다).
- 용어 분리: 이미 연결된 동기화 폴더를 내 PC에 얹는 것 = **Link**, OAuth로 새 계정을
  붙이는 것 = **Connect**(사용자 지시).

### 폴더 열기·전송 진행 표시 (`e9bd6b4`·`085ca7d`)

사용자 설계 요청 → A(플레이스홀더 행 `불러오는 중…`) + B(플로팅 배지) **둘 다 채택**,
전송 진행은 **로컬 복사 진행 창 재사용**으로 확정.

### 로딩이 끝나지 않던 3+2건 (`9df7857`·`801e167`·`d936b2d`)

한 증상에 원인이 여러 개였다.

- **This PC의 클라우드 행만 갱신 안 됨**: 핸들러가 패널 루트 경로만 봐서 `::PC::`가
  매칭에서 빠졌다 → `panel_shows_cloud`(클라우드 경로 **또는** 내 PC).
- **영원한 `불러오는 중…`**: ① Google ID 캐시가 메모리 전용이라 재시작 후 미상
  → 루트부터 걸어 해결(`resolve_google_id`) ② **실패를 캐시하지 않아** 무한 재시도 +
  오류가 보이지 않았다 → 실패도 `[!] 사유` 행으로 캐시.
- **비활성 탭 미갱신**: 세션 복원 탭은 콜백 등록 **전**에 만들어져 비어 있었다

- **경로 바 조각 클릭 무동작**: `cloud_from_display`가 루프 안에서 `?`를 써서,
  클라우드가 아닌 추가 루트(Link) 하나가 함수 전체를 조기 종료시켰다 → `continue`.

### 계정 간 복사 (`cc8df2a`·`34a1e21`·`5b9842a`·`05794f3`·`5278a14`)

서버 사이드 복사는 같은 드라이브 안에서만 되므로 **임시 폴더 경유**(다운로드 → 업로드)가
유일한 경로. 이후 QA가 진행률 계산을 네 번 교정했다.

- **대상 폴더를 만들지 않아** 복사가 "되는 것처럼" 진행되고 결과가 없었다
  → 깊이 오름차순 `ensure_folder`. 이때 OneDrive 폴더 생성이 `conflictBehavior:
  replace`였던 것도 발견 — **기존 폴더를 지울 수 있는 값** → `fail` + 무시.
- **건수를 바이트 자리에 넣어** "0 B / 6 B" 표시 → 목록 크기로 총량 선확정.
- **36MB 업로드가 끝나야 한 번에 반영**: Google이 단일 multipart라 중간 보고가
  원리적으로 불가능했다 → `uploadType=resumable` 5MB 청크(중간 308이라 마지막만 검사).
  진행 콜백도 OneDrive 전용이던 것을 3사로 배선.
- **100%에서 멈추고 [취소]도 무반응**: ① 계정 간 복사가 다운로드만 집계하고 업로드는
  콜백 없는 경로였다 → 세그먼트를 앞/뒤 절반으로 분할 ② 취소 판정이 **워커의 진행
  통지 처리기 안에만** 있어 통지가 멎으면 버튼을 읽지도 않았다 → `TIMER_CLOUD_POLL`
  200ms로 통지와 분리.

### Dropbox 실사용 (`0c5a3e8`·`e3032a9`·`28a728b`·`25c51f2`·`858f087`)

사용자가 App key/secret을 발급해 오면서 실사용에 들어갔고, **5건이 연달아** 나왔다.

- **scope가 읽기 전용**이었다(4차 쓰기 이전에 작성된 값) → write 2종 추가.
  기존 연결은 재연결해야 새 토큰을 받는다.
- **리디렉션 정확 일치**: 콘솔 등록값이 `http://localhost:5368{2,3,4}`(슬래시 없음)인데
  `:42813/`을 보내고 있었다 → `Service::redirect_ports`/`redirect_slash`로 제공자별
  규칙을 정의에 둠. 후보 전부 점유 시 **임의 포트 폴백을 일부러 금지**(폴백해도 거부).
- **라벨 "Dropbox – account" + This PC 미표시**: `me_url`이 비어 있었고(Dropbox RPC는
  POST 전용이라 `http_get`으로 못 받아 1차에서 생략) → `me_post`·`http_post_bearer`.
  더 나쁜 쪽은 **`is_api()`가 account 유무를 조건으로 삼아** 계정을 못 받은 연결이
  vfs 추가 루트에서 통째로 빠진 것 — 라벨 부실과 연결 부재는 별개다 → 경로 유무로 판정.
- **한글 이름 업로드 실패**: Dropbox content API는 경로를 `Dropbox-API-Arg` **헤더**로
  받는데 헤더는 ASCII 전용이다 → `json_escape_hdr`(비ASCII `\uXXXX`·서러게이트 쌍).
- **"ABC새폴더" → "ABCuc0c8ud3f4ub354"**: 업로드는 처음부터 정상이었고 **읽기**가
  범인 — `json_str`이 `\uXXXX`를 모르고 `other => other`로 백슬래시만 버렸다.
  깨진 이름으로 경로를 다시 조립해 조회하니 **HTTP 409 not_found**까지 이어졌다
  (표시만의 문제가 아니라는 증거). Graph·Google은 UTF-8 그대로 줘서 증상이 없었다.

## client_id 소유 모델 정정 — 하이브리드 (사용자 지적 — ADR-0006 §2-4 개정)

사용자 지적: **"NexaDir 기준으로 ID를 발급받아야 하는 것 아닌가"** → **타당**.
초판 ADR의 "1차 사용자 제공"은 **Google 제약 하나를 3사 전체에 과적용**한 것이었다.
정상 모델은 벤더 1회 등록이며, 서비스별로 요건이 갈린다(원천 조회 후 정정):

| 서비스 | 벤더 등록 | 비용 | 제약 |
| --- | --- | --- | --- |
| OneDrive(Entra) | ✅ 권장 | **무료** | 게시자 인증(선택)으로 경고 제거. **scope를 `Files.Read.All`→`Files.Read`로 하향**(조직 계정 관리자 동의 요구 회피) |
| Dropbox | ✅ 권장 | **무료** | 개발 상태 최대 500명, **50명 연결 시 2주 내 프로덕션 승인 신청**(무료) |
| Google Drive | ⏸ 보류 | **연 $500~4,500** | `drive.readonly` = restricted scope → CASA 연간 유료 감사+재검증. `drive.file`은 감사 면제지만 앱 생성 파일만 보여 **탐색기로는 무용** |

**채택 = 하이브리드**(rclone 관례): `Service::default_client_id` 상수(현재 3종 모두 빈
문자열) → **설정 `cloud_client_id_<종류>` 우선, 없으면 기본값**. 등록 완료 시 **상수만
채우면** 재배포로 전 사용자 적용.

근거(포터블 특유): 동봉 ID는 PKCE 공개 클라이언트라 시크릿 유출은 아니지만 **전 사용자가
쿼터를 공유**하고 악용 시 앱 등록이 정지되어 전원이 끊긴다 → 기본값을 주되 **재정의 경로를
항상 열어 둔다**.

- 코드: `resolve_client_id()` + 회귀 테스트(설정 우선·공백=미설정·둘 다 없으면 안내 경로).
- 안내 문구 3종 개정("기본 ID 동봉하지만 이 서비스는 직접 발급 필요" + 전용 쿼터 팁).
- **235 green·clippy 0·3.28MB·B3 통과**. **사용자 액션 = OneDrive·Dropbox 등록**(무료).

### 2차 탐색 (`db96d8d`)

사용자 QA: "연결했는데 This PC에 안 보이고 Go to Folder도 무동작".
진단 = **인증은 완전 성공**(`cloud0`에 계정 이메일·DPAPI 토큰 1356B) — 탐색이 없어

## X-37 Connect Cloud — 브라우저 OAuth 직접 연결 (사용자 결정 — 같은 브랜치 6커밋째)

- PKCE 공용 클라이언트(`client_secret` 미사용·미동봉) · **루프백 리디렉션**

- **B3 화이트리스트 +4**: `winhttp`·`crypt32`·`ws2_32`·**`bcrypt`**.
